# 크리에이터 매칭 추천 프로토타입

광고주가 **예산 · 카테고리 · 팔로워 규모**를 입력하면, 조건에 맞는 크리에이터를 성과 지표 기반으로 추천하는 프로토타입입니다.

모비데이즈 P&A 사전 과제 · 이용환 · 2026.08

---

## 먼저 읽을 것 — 데이터가 뒤집은 판단 4가지

이 프로토타입에서 가장 중요한 결정들은 **처음 세운 가설이 계산 결과로 뒤집힌 것**입니다.

**① 신인을 "공정하게" 처리해도 소용없었습니다**
평점 결측 27명에게 중앙값을 채워주면 불이익이 없다고 봤는데, 시뮬레이션하니 **TOP50 진입 0명**이었습니다. 집행 경험 축에서 전원 0점이라 구조적으로 못 올라옵니다. 가중치로 풀 수 없는 문제여서 **점수 조정이 아니라 노출 구조 분리**로 방향을 바꿨습니다.

**② 인스타그램이 실력과 무관하게 상위를 차지하고 있었습니다**
조회수÷팔로워 중앙값이 유튜브 20.9% · 인스타그램 33.1%로 **1.6배** 차이납니다. 섞어서 줄 세우면 인스타가 구조적으로 유리해집니다. 플랫폼별로 나눠 백분위를 매기자 TOP10이 유튜브 6 : 인스타 4로 균형을 찾았습니다. **코드는 정상 동작 중이었고, 아무도 이걸 버그라 부르지 않았을 겁니다.**

**③ 광고주 평점은 대체 불가능한 독립 신호였습니다**
다른 지표와의 상관이 전부 ±0.07 이내(참여율 -0.02 / 집행건수 0.04 / 도달 0.07 / 단가 0.02). 규모가 크다고, 비싸다고 평점이 오르지 않습니다. 실제로 **이 축을 빼면 TOP10이 4/10으로 무너집니다** — 30% 가중치의 근거입니다.

**④ 가중치 45/30/25는 최적값이 아닙니다. 그게 문제가 아니라는 걸 확인했습니다**
40/35/25로 바꿔도 TOP10이 **동일**하고, ±5 범위에서는 순위가 거의 안 움직입니다. 반면 축을 제거하면 4~6/10으로 붕괴합니다. **중요한 결정은 "비율"이 아니라 "어떤 축을 쓸까"였습니다.**

> 위 숫자는 전부 `analysis/` 스크립트로 재현할 수 있습니다. 로직 전체는 **310,365회 자동 검증**(전 구간 19,305회 + 실사용 구간 10만원 단위 291,060회)을 오류 0건으로 통과했습니다.

## 실행 방법

의존성 설치나 빌드가 없습니다. 저장소를 받아 로컬 서버로 열면 됩니다.

```bash
git clone <repository-url>
cd <repository-name>
python3 -m http.server 8000
```

브라우저에서 **http://localhost:8000** 접속.

> `index.html`을 더블클릭해 `file://`로 열면 브라우저 보안 정책(CORS) 때문에 CSV를 읽지 못합니다. 이 경우 화면에 안내 문구가 표시되며, 위 방법으로 실행하면 정상 동작합니다.
> Node 환경이라면 `npx serve` 또는 VS Code의 Live Server도 동일하게 동작합니다.

## 파일 구성

```
index.html            프로토타입 전체 (HTML + CSS + JS, 단일 파일)

```

## 추천 로직 요약

### 1단계 — 필터

```
카테고리 ∈ 선택 (미선택 시 전체)
팔로워    ∈ 선택한 규모 구간
단가      ≤ 입력한 총예산
```

### 2단계 — 스코어 (0~100)

```
score = 실질 도달 45% + 광고주 평점 30% + 집행 경험 25%
        (실질 도달 = 평균 조회수 × 참여율)
```

각 지표는 **선택한 팔로워 구간 안에서, 다시 플랫폼별로 나눠** 백분위로 환산합니다(근거는 아래 트레이드오프 참조).

### 3단계 — 분리 노출

- **추천 크리에이터** — 캠페인 이력이 있는 검증 후보
- **미검증 후보** — 이력이 없어 성과 예측이 어려운 후보 (태그로 명시)

### 점수 외에 함께 제공하는 판단 재료

- **도달 1인당 비용(CPR)** — `단가 ÷ 실질 도달`. 이 데이터에서 111원 ~ 55,089원으로 **498배** 차이납니다. 정렬 축과 카드 표시로 제공하되, 점수 가중치에는 넣지 않았습니다.
- **도달률 주의 태그** — 팔로워 대비 조회수가 **같은 플랫폼 하위 10%** 인 경우 확인을 요청합니다.

## 설계 근거와 트레이드오프

### 조회수와 참여율을 곱해서 하나의 축으로 만든 이유

두 값을 각각 가중 합산하는 방법도 있었지만, 데이터를 확인하니 **참여율은 변별력이 거의 없었습니다.**

```
engagement_rate: p25 6.47 / 중앙값 7.10 / p75 7.90 (전 구간 폭 1.4%p)
```

전체가 좁은 구간에 몰려 있어 단독 지표로 순위를 만들면 소수점 차이가 결과를 좌우합니다. 반면 `평균 조회수 × 참여율`은 **실제로 반응한 사람 수**라는 해석 가능한 값이 되고, 조회수만 높고 반응이 없는 채널과 규모는 작지만 반응이 좋은 채널을 함께 평가할 수 있습니다.

**트레이드오프:** 곱셈은 조회수가 큰 채널에 유리합니다. 이 편향은 **선택한 팔로워 구간 안에서만 백분위를 계산**하는 것으로 상쇄했습니다. 매크로를 선택하면 매크로끼리, 나노를 선택하면 나노끼리 비교됩니다.

### 절대값이 아니라 백분위를 쓴 이유

조회수(만 단위)·참여율(한 자릿수 %)·평점(5점 만점)은 단위가 달라 직접 합산할 수 없습니다. 정규화 방식으로 min-max도 검토했으나, 이 데이터는 **조회수 최대값이 295,892로 중앙값(5,527)의 53배**인 롱테일 분포라 min-max를 쓰면 상위 1~2명이 척도 전체를 차지합니다. 백분위는 이상치의 영향을 받지 않습니다.

**트레이드오프:** 백분위는 순위만 반영하므로 "1등과 2등의 격차"를 표현하지 못합니다. 이를 보완하기 위해 카드에 실제 값(평균 조회수·실질 도달·단가)을 함께 노출했습니다.

### 백분위를 플랫폼별로 나눠 계산한 이유

처음에는 팔로워 구간 안에서 전체를 한 줄로 세웠습니다. 그런데 **유튜브와 인스타그램은 지표의 기준선 자체가 다릅니다.**

```
조회수 ÷ 팔로워 중앙값 —  유튜브 20.9%  ·  인스타그램 33.1%   (1.6배)
```

인스타그램은 팔로워 대비 조회수가 구조적으로 높게 나오는 플랫폼이라, 섞어서 줄 세우면 **인스타그램 계정이 실력과 무관하게 상위를 차지합니다.** 플랫폼을 나눠 각 그룹 안에서 백분위를 매기도록 바꾼 뒤 TOP10 구성이 유튜브 6 : 인스타그램 4로 균형을 찾았습니다.

**트레이드오프:** 두 플랫폼의 점수를 직접 비교할 수 없게 됩니다("유튜브 82점 vs 인스타 82점"의 의미가 다름). 대신 플랫폼 선택 필터를 제공해, 비교가 필요하면 한 플랫폼 안에서 보도록 했습니다.

### 예산 효율(CPR)은 표시만 하고 점수에는 넣지 않았습니다

`단가 ÷ 실질 도달`을 계산해보니 **최저 111원 ~ 최고 55,089원, 498배 차이**가 났습니다. 광고주에게는 가장 직접적인 의사결정 정보인데 기존 3축 어디에도 담기지 않았습니다 — 실제로 **점수 TOP10과 효율 TOP10은 절반만 겹쳤습니다.**

그럼에도 가중치에 넣지 않은 이유는, 효율만으로 줄 세우면 **단가가 싼 나노 채널이 항상 1위**가 되기 때문입니다. 도달 절대량이 필요한 캠페인에서는 이것이 오답입니다. "효율이 좋은 것"과 "캠페인 목표를 달성하는 것"은 다른 문제라, 값을 보여주고 정렬 축을 주되 **판단은 사용자에게 남겼습니다.**

### 축이 서로 겹치지 않는지 상관계수로 확인했습니다

가중 합산은 축끼리 같은 정보를 담고 있으면 그 정보에 이중으로 가중치를 주게 됩니다. 그래서 축 선정이 유효한지 계산해봤습니다.

```
광고주 평점 ↔ 참여율 -0.02 · 집행건수 0.04 · 실질도달 0.07 · 단가 0.02
단가       ↔ 팔로워 0.74 · 실질도달 0.71 · 참여율 -0.51
```

**평점은 어떤 지표로도 대체되지 않는 독립 신호였습니다.** 이 축을 빼면 다른 데이터로는 알 수 없는 정보를 통째로 잃습니다 — 30% 가중치의 근거가 됩니다.

반대로 **단가는 규모의 함수에 가까웠고, 참여율과는 음의 상관(-0.51)** 이었습니다. 비싼 채널일수록 팬의 반응 밀도는 오히려 떨어진다는 뜻입니다. 단가를 점수 축이 아니라 필터 조건과 효율 지표로만 쓴 이유입니다.

### 팔로워 수 자체에는 가중치를 주지 않았습니다

규모는 이미 사용자가 **입력 조건으로 선택**한 항목입니다. 선택한 밴드 안에서 다시 팔로워로 점수를 주면 "마이크로를 골랐는데 마이크로 중 제일 큰 채널이 1등"이 되어, 사용자의 선택을 사실상 무시하게 됩니다.

### 신인(캠페인 이력 없음) 처리 — 시뮬레이션으로 방향을 바꾼 부분

`advertiser_rating` 공란 27명은 확인 결과 **전원 집행 이력이 0건인 신인**이었고, 팔로워 중앙값은 오히려 전체의 2.6배였습니다.

처음에는 "평점을 중앙값으로 채우면 공정하다"고 가정했으나, **실제로 계산해보니 그렇지 않았습니다.**

| 처리 방식 | 27명의 순위 (최고/중앙/최저) | TOP50 진입 |
|---|---|---|
| 0점 처리 | 132 / 184 / 200위 | 0명 |
| 중립 처리 | 65 / 152 / 200위 | 0명 |

평점을 보정해도 **집행 경험 축에서 전원 0점**이라 구조적으로 상위에 오를 수 없었습니다. 가중치 조정으로는 풀리지 않는 문제였고, 그래서 **노출 구조를 분리**하는 방향으로 바꿨습니다. 점수는 중립 처리하되 섹션을 나누고, 태그로 미검증임을 명시합니다.

**트레이드오프:** 섹션이 늘어 화면이 길어집니다. 대신 "왜 이 사람은 안 보였나"를 설명할 수 없는 시스템이 되는 것을 피했습니다.

### 예산은 총예산으로 해석했습니다

과제에 정의가 없어 **캠페인 총예산**으로 해석했습니다. 광고주가 기획 단계에서 갖고 있는 숫자는 1인당 단가가 아니라 캠페인 예산이고, 실제 집행도 여러 명 믹스가 일반적이기 때문입니다. 단가가 예산보다 낮다고 감점하지 않으며, 남는 예산은 조합 여력으로 봅니다(별도 탭인 조합 제안에서 활용).

### 단가 0원 처리 — 과제에 명시되지 않은 예외

과제는 `advertiser_rating` 공란을 예고했지만, 확인해보니 **`avg_campaign_budget_krw`에 0원인 행이 27건**(신인과 동일 인원) 있었습니다. 이를 그대로 두면 `0원 ≤ 모든 예산`이 되어 **어떤 예산 조건에도 무조건 통과**합니다. 결측과 동일하게 취급해 **카테고리별 단가 중앙값으로 추정**하고, 추정치임을 카드에 명시했습니다.

### 후보가 0명일 때

빈 화면 대신 **계산된 완화안**을 제시합니다. 각 제안에는 그 조건으로 바꿨을 때 몇 명이 나오는지를 함께 표시해, 사용자가 결과를 예측하고 선택할 수 있게 했습니다.

```
예) 예산을 570만원으로 상향 — 이 조건의 최저 단가 5,670,000원 기준
    팔로워 규모를 '마이크로'로 변경 — 12명 추천 가능
    카테고리 제한 해제 — 전체 카테고리 기준 34명
```

- **촘촘하게** — 실사용 구간을 **10만원 단위로**: 50만~2,000만원 196종, 조합 계산 **291,060회**

| 테스트형에 신인 2명 이상 배정 | 0건 |
| **예산 역전 (10만원 올렸는데 결과가 나빠짐)** | **0건** |

마지막 항목은 예산 간격이 넓으면 드러나지 않아 **10만원 단위로 좁혀야 잡히는** 문제입니다. 사용자가 가장 납득하기 어려운 종류의 오작동이라 별도로 검사했습니다.

초기 검증에서 **"채울 수 있는데 못 채운 조합"** 항목에 19건이 걸렸습니다. "다른 조합 보기"의 후보 회전이 저단가 재구성 단계까지 적용돼, 예산으로 채울 수 있는데도 인원을 못 채우는 경우가 있었습니다. 회전 결과가 목표에 미달하면 회전 없이 다시 구성하는 단계를 추가해 해소했습니다.

## 기술 선택

**프레임워크 없이 단일 HTML 파일**로 만들었습니다.

이 과제의 평가 대상은 추천 로직의 설계 근거와 문서화입니다. 빌드 도구를 도입하면 검토자가 `npm install`부터 해야 하고, 로직은 여러 파일에 흩어집니다. 단일 파일은 정적 서버 하나로 실행되고 전체 로직을 한 번에 읽을 수 있습니다.

- 외부 라이브러리 없음 (CDN 포함 없음)
- CSV 파싱·스코어링·렌더링 모두 순수 JavaScript
- 제공된 CSV는 **수정 없이 원본 그대로** 사용 (모든 예외 처리는 코드 내에서 수행)

## 한계

- 가중치(45/30/25)는 실무 판단에 근거한 초기값이며, 실제 캠페인 성과와 대조 검증된 값이 아닙니다. 다만 민감도 분석으로 **±5 범위에서는 결과가 바뀌지 않고, 축을 제거하면 무너진다**는 것을 확인했습니다 — 정밀한 값을 특정할 수는 없지만 정밀할 필요가 없다는 것까지는 말할 수 있습니다. (`node analysis/sim_weights.js`)
- CSV 파서는 이 데이터 형식(따옴표·줄바꿈 없는 단순 CSV)에 맞춘 최소 구현입니다.
- 조합 제안은 그리디 방식이라 최적해가 아닙니다. 예산 소진율과 도달 합계를 함께 표시해 사용자가 판단하도록 했습니다.
- CPR과 도달률 태그는 단일 시점 스냅샷 기준입니다. 활동이 중단된 채널의 낮은 도달률을 품질 문제와 구분하지 못합니다.
- 저예산 구간의 커버리지가 낮습니다. 데이터의 최저 단가가 30만원대라 그 아래 예산에서는 후보가 나오지 않습니다(50만원 이상 구간의 0명 비율 24%, 500만원 이상 8~13%). 완화안조차 제시하지 못하는 경우는 0.1%입니다. 예산대별 수치는 [PRD.md](./PRD.md)의 커버리지 표 참조.
- 팬 연령·충성도·활동 빈도·팔로워 추세 등 실제 매칭에 중요한 지표는 데이터에 없어 반영하지 못했습니다. 상세는 [PRD.md](./PRD.md#5-데이터에-없어-반영하지-못한-지표) 참조.
